# ADR-0075: Print a short Claude connect result and keep the rules in the skill

Status: accepted (2026-10-06).
Supersedes: none
Superseded by: none

## Context

In the live P7.2 run, `/ariadne-connect` printed about 10 KB into the Claude
conversation: the full shared agent rules (`integrations/rules/claude.md`, 9.3 KB)
plus the JSON receipt. Claude Code reads command output into model context, so that
text cost tokens on every later turn. The rules are identical for every connection.
Only the routing IDs (binding and generation) differ per session.

## Decision

- The Claude skill (`integrations/claude/plugin/skills/ariadne/SKILL.md`) carries the
  full rules, generated by `cargo xtask gen-rules` the same way the Codex skill is.
  Claude loads it on demand, once per session.
- The skill's Claude block says `/ariadne-connect` prints the binding and generation
  and that the rules are in the skill.
- `/ariadne-connect` prints one short plain-text line: session, project, binding,
  generation, dispatch and connection state, the `[ARIADNE_INPUT:<input>:<attempt>]`
  hint and a pointer to the skill. The explicit-session resume guidance is still
  appended. `setup.js` still validates the receipt's `setup_instruction` (64 KiB
  bound) but no longer returns or prints it.
- `/ariadne-status` and `/ariadne-disconnect` keep their small JSON output.

## Consequences

- The skill grows to about 12 KB, loaded once on demand instead of about 10 KB per
  connect.
- Codex is unchanged: the owner still pastes the setup instruction.
- The core still sends the setup instruction. The Claude Mod ignores it; the desktop
  still shows it for Codex.
- The live acceptance plan has no Claude paste turn.
