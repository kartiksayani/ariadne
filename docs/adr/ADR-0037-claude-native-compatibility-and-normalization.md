# ADR-0037: Ground Claude compatibility in actual SDK identity and native resources

Status: Accepted

## Context

P3.4 consumes the P0.5 adapter seam and the captured P3.3 Mod lifecycle. The preserved 2.1.287 SDK describes `plugin` as `{name,root}` (the plugin as loaded); it has no `plugin.version`. The working archived Mod likewise uses `$.plugin.root`. The previous version-property check prevented a real supported SDK instance from qualifying, while numeric `Date.now()` event timestamps did not satisfy canonical `UtcMillis`.

## Decision

Use actual SDK loaded plugin name/root and the imported immutable descriptor's helper/app/API identity. The Mod checks the actual fields, selected engine version and helper version; it does not claim native qualification. Native code compares the **exact SDK-reported root** manifest and fixed Ariadne resource checksums against the explicit installed bundle, verifies canonical project/helper/executable identity, and checks both version commands. Never crawl plugin caches or fall back to PATH, configuration, transcripts or a development helper. Native inspection uses directory-relative no-follow resource reads, this user's UID and non-writable-by-other-users modes, bounded sizes and one absolute five-second IO deadline on a dedicated bounded worker. Only owned `--version` children may be reaped; no running host is launched, signalled or resumed.

This proves version/cache parity after reload, not cryptographic attestation of every byte in host memory. P6 must install immutable version directories and refuse replacing a same-version bundle with different bytes. P3.7 owns the actual UID-checked announcement producer/intake, association and 30s heartbeat/90s freshness. The native-only evidence seam is not deserialized from a renderer or provider claim of `parity=true`: it contains actual loaded root/name, descriptor helper/app/API, engine/external-session/canonical-project identity, native observation time and optional current binding/generation. Missing or unverifiable evidence is Unknown/unavailable; a concrete mismatch requires reload or update. A later changed/disappeared identity during qualification is rejected. Exact supported CLI and SDK version remains 2.1.287; read-only observation of 2.1.289 does not qualify it.

A known empty native evidence slot after connect emits canonical Presence with connection/execution/freshness Unknown, no last-seen/source and current native observation time. It does not report host exit, Idle, failed delivery or resend permission. Fresh/stale snapshots retain their original last-seen and observation times; stale evidence does not refresh a heartbeat. Private presence IDs hash compact JSON of provider identity tag, binding and the complete presence snapshot, including instance/generation/freshness. Identical snapshots replay identically; Fresh→Stale or loss of evidence changes identity. Presence is ephemeral and has no lifecycle checkpoint/backpressure reservation.

Mod lifecycle continues through the existing bridge report→Core route. Native `submit` is Unsupported for this pull adapter. Native `observe` has no independent turn/history source and never infers Idle. `reconcile` returns every requested attempt as unresolved, accepts old observation tokens without interpreting them as delivery absence, and does not advance a fabricated checkpoint. Requests are capped at 100 attempts with nonempty markers≤4KiB; invalid_argument instructs a narrower batch. There is no second transport, event broker, Core dependency or duplicate result/turn join. Composition must re-read persisted unsealed attempts after later Mod report commits before opening claim admission; this remains a P2.2/P3.2/P3.7 acceptance join.

The provider-local normalizer parses≤8MiB actual Mod JSON through canonical Rust DTOs and their validator, retaining original IDs/scope/timestamps/receipts and diagnostic limits. Connection/presence facts require native qualification and are rejected as Mod callbacks. Conflicting terminal facts remain distinct payloads under the same canonical terminal identity so Core can detect conflict. Neither normalization nor an old-generation callback grants current authority or fabricates a trusted historical scope. Both Mod timestamp producers now emit ISO UTC millisecond strings via `toISOString()`.

## Evidence and remaining joins

Source-backed JS fixtures and native conformance tests cover all emitted lifecycle kinds, terminal contradictions, malformed/numeric/oversized Unicode data, original callback scope, version/resource/cache mismatches, missing/stale evidence, explicit connection identity and bounded owned version-child timeout. A nested receipt is a canonical constructor conformance fixture; the actual Mod still emits accepted with receipt:null. No live new-version qualification was run.

The first-party trait implementation and pure conformance boundary are reviewable independently. Actual P3.7 intake, P6 immutable installation/rendering, owner CLI/native qualification, and durable production Core/runtime result/turn ordering remain explicit acceptance work. The existing-session structured context feature is tracked by PR54/ADR0038; its owner issuance and selector do not replace these joins or transfer host memory.
