# Claude Mods communication POC

Target: Claude Code **2.1.287**, already running in an interactive terminal.

**Live POC passed:** three external messages, sequential turns in the existing
conversation, retained context, busy queuing and replies captured back into the
mailbox. [Results and limits](RESULTS.md).

This small mod receives external messages into that conversation with
`$.prompt.submit`, and sends final replies back to a local mailbox through
`turn.complete`. No new Claude process, `--resume`, terminal keystrokes, or MCP
server is used for message delivery.

## Attach to your existing conversation

Run these **inside the already-open Claude terminal**, one at a time:

```text
/plugin marketplace add /Users/owner/Documents/Code/ariadne/poc/claude-mods
/plugin install ariadne-poc@ariadne-poc-local
/reload-plugins
/ariadne-connect
```

Approve the local plugin if Claude asks. Copy the printed `session` and `project`.
The plugin is installed in your Claude configuration by these commands. It starts
polling after `/ariadne-connect`; other sessions remain unbound.

## Send messages from outside Claude

From a shell at the Ariadne repository root, substitute the actual session ID:

```sh
rtk proxy python3 poc/claude-mods/send.py SESSION_ID 'Explain your first finding.' --item finding-1
rtk proxy python3 poc/claude-mods/send.py SESSION_ID
```

The second command prints queue states, replies and lifecycle events. If the
connected session's `project` differs from the Ariadne repository, add
`--project '/absolute/path/printed/by/connect'` to either command.

For the automated three-message exercise:

```sh
rtk proxy python3 poc/claude-mods/exercise.py SESSION_ID
```

It sends a random phrase, waits until Claude starts working, queues two more
messages, then checks context retention, three distinct turns, ordered completion,
and queue insertion during the first turn. It makes **three real Claude turns**
using that session's existing model and authentication. It does not launch Claude.
Results are saved under the connected project's `.ariadne-mods-poc/` directory.
If the first turn finishes before the busy observation, that check fails honestly;
the script does not manufacture a busy result or retry automatically.

To demonstrate context from **before connection**, first tell Claude a random
phrase in its terminal, then connect and use `send.py` to ask for it without
repeating the phrase. The automated exercise proves continuity across its own
three turns; this extra check proves access to earlier terminal context.

## What is implemented

- One-second polling; no inference for empty polls.
- Explicit session ID and project binding; generation checks fence old dispatchers.
- Transactional single claim, one outstanding input, FIFO within a session.
- Input ID embedded in the prompt, matched to `turn.start` and `turn.complete`.
- Main-loop replies only; unrelated or subagent completions cannot drain the queue.
- Errors, interruptions and uncertain claimed work pause further delivery.
- Owner message and item ID preserved together; replies stored against that input.
- Plugin attribution preserved; no tool permission changes or credential access.

SQLite and Python are **POC fixtures**, not a revision of Ariadne's production
storage design. There is no tree UI or agent-driven tree mutation in this POC.
The item IDs are labels for verifying message/reply association.

## Local checks

```sh
rtk proxy claude plugin validate --strict poc/claude-mods/plugin
rtk proxy claude plugin validate --strict poc/claude-mods
rtk proxy python3 -m unittest poc/claude-mods/test_broker.py
rtk proxy node --test --experimental-default-type=module poc/claude-mods/test_mod.mjs
```

The broker tests use actual SQLite. The Node tests use the actual mod with a
simulated Claude host; they do **not** establish real prompt delivery. Installed
version types were generated by Claude itself when loading with `--plugin-dir`.

## Limits and recovery

Keep the session open during the exercise. After reload, run `/ariadne-connect`
again. An outstanding claimed/running/failed input causes the reconnected queue
to remain paused; this POC intentionally has no automatic replay or recovery UI.
Inspect the stored events before deciding how to recover. A session switch stops
the old binding. Ordinary terminal input and other plugins can interleave; this
queue does not claim priority over them. Prompt rewriting by another plugin can
prevent correlation and stall delivery rather than falsely mark it completed.

To stop the bridge, disable the plugin in `/plugin` and run `/reload-plugins`.
To remove it, use `/plugin uninstall ariadne-poc@ariadne-poc-local`. The local
mailbox remains for inspection; it contains the test prompts and replies.

Organization security guidance was not checked, following the existing the review tool waiver.
